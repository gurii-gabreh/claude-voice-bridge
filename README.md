# Claude Voice Bridge

claude.ai / Gemini(ブラウザ版)との会話を、音声で行うためのChrome拡張機能です。サイドパネルのオーブをクリックして話すと、内容が自動で入力欄へ入力・送信され、応答が読み上げられます。「Claude」「Gemini」と呼びかけると対象AIを切り替えられます。

## 未解決の相談・進行中タスクの見逃し防止(2026-09-12追加、2026-09-13大幅改修)

音声での対話が続くと、その場で出てきた相談ごとや作業が「結局あれは解決したのか、まだ返事していないのか」分からなくなるという課題があったため追加。

サイドパネル上部の「🎙️ ボイス」「📋 一覧」タブで、通常の音声対話画面(ボイスモード)と、このトラッカー画面(一覧モード)を切り替える(2026-09-13追加)。定例文セクションはどちらのモードでも表示されるが、普段は折りたたんだ状態になっている。

### 検出方式(2026-09-13、正規表現マーカー方式から全面移行)

当初は【相談NNN】【処理開始NNN】【処理完了NNN】(progress-tracker-dashboardのCLAUDE.mdルール14マーカー)を正規表現で検出する方式だったが、AI(Claude)側が毎回マーカーを付け忘れ続け信頼できないという指摘を受け、**完全に廃止した**。代わりに、一覧モードの「🔍 ルームタスク一覧を抽出」ボタンを押すと:

1. `room-task-audit`スキル(`progress-tracker-dashboard`の`.claude/skills/room-task-audit/`)を起動する固定フレーズ「room-task-auditスキルを呼び出して実行してください。」をチャット入力欄へ自動送信する(音声モードの送信・応答待ちの仕組みをそのまま流用。通常の会話ターンが1往復増えるだけで、別料金のAPIは呼ばない)。**2026-09-13不具合修正**: 当初は先頭が`/`の`/room-task-audit`を送信していたが、claude.ai/codeの入力欄では先頭`/`がClaude Code組み込みのスラッシュコマンド/スキル選択ポップアップを開いてしまい、送信ボタン・Enterキーがそのポップアップの選択操作に奪われて実際には送信されない(抽出ボタンを押しても応答が来ず固まる)不具合があったため、先頭`/`を使わない言い回しに変更した
2. AI自身がそのルームを直接読み返し、未解決の相談・未完了の作業を`[ROOM-TASK-AUDIT-START]`〜`[ROOM-TASK-AUDIT-END]`の固定形式(種別|内容|引用|不確実)で報告する
3. `sidepanel.js`がこれをパースし、`TrackerStore.setItems()`で表を丸ごと置き換える(1回の抽出=その時点での「今の状態」のスナップショット。既に解決済みの項目はAIが最初から含めないので、削除操作は基本的に不要)

同時に、常時監視(`cvb-passive-message`)・音声応答経由でのマーカー自動スキャンは行わなくなった(`RoomLogStore`への全文記録自体は引き続き行う)。

### 表の項目

- 各項目は「タスクID」(表示順の通し番号)・種別(相談/未完了作業、内容欄に含まれる)・内容(要約)・ルーム(検出元タブのサイト+タイトル)・ステータスを持つ。AIが「不確実」と判断した項目には badge に「・不確実」が付く
- **タスクIDボタンをクリックすると、ルーム内で該当のタスクID(固定書式`【タスクID:N】`、room-task-auditスキルが要約の語尾・関連する回答の先頭に必ず埋め込む。SKILL.md参照)が書かれている箇所へ自動スクロールする**(2026-09-13追加、2026-09-13再改修)。同じタスクIDが複数箇所に出てくる場合、連続してクリックすると出現箇所を順番に巡回する(最後まで行くと最初に戻る)
- **📋ボタンで内容をコピー**できる(`navigator.clipboard.writeText`。2026-09-13追加)
- ✕ボタンは「一覧から外す」(`status: "done"`にしてJSONには残す)。次に抽出した時、まだ実際に未解決ならAIが改めて拾い直す
- `chrome.storage.local`(キー: `cvb_tracker`)に保存するため、サイドパネルを閉じて開き直しても直近の抽出結果は残る

### その他のデータ層

- `room-log-store.js`(`window.RoomLogStore`)は、マーカーの有無に関わらず捕捉できた発言を全文そのまま`chrome.storage.local`(キー: `cvb_room_log`)へ逐次追記する(2026-09-12追加、ユーザー指示「全て拾え」)。サイドパネルでの表示は行わない(データ保持のみ)。これに伴い`manifest.json`へ`unlimitedStorage`権限を追加した
- 「☁️ GitHubへ同期」ボタン: 押した時だけ、その時点のトラッカー全体をGAS中継(`gas/`参照、study-appとは別プロジェクト・別PAT)経由でこのリポジトリの`data/tracker.json`へ上書き保存する。自動同期はしない
- ルーム内容のナレッジ化: 「🔍 ルームタスク一覧を抽出」ボタンを押すたびに、その1回分の生の抽出結果(要約せず全文)を同じGAS中継経由で`data/knowledge-log.json`へ1件追記する。音声応答(Voiceモード)・常時監視からは行わない(ボタンを押した時だけ)
- **限界(ユーザーに説明済み)**: `chrome.storage.local`(トラッカー・全発言ログ)自体は依然、この拡張機能が入っているブラウザ・端末に閉じたデータ。GitHub同期は上記2つのボタンを押した範囲でのみ行われ、それ以外(RoomLogStoreの全発言ログ自体)はGitHubには送られない(送るたびに肥大化するため、あえて対象外にしている)。また、Claude Code本体のセッション要約(コンテキスト圧縮)による会話本体の情報欠落を防ぐものでもない(この拡張機能の管理外)。room-task-auditスキルはprogress-tracker-dashboardリポジトリに置かれているため、そのリポジトリのセッション以外では動作しない

## できること・できないこと

- 音声認識(Web Speech API)・読み上げ(SpeechSynthesis)はブラウザ標準機能のみを使用。追加のAPI契約・料金は発生しません(v0.6.0の読み上げ音声選択も、ブラウザに標準搭載済みの音声から選ぶだけで追加コストは発生しません)
- 公式のclaude.ai / Geminiページをそのまま操作するだけで、Claude Code等の別ツール(harness)には該当しないため、各社の利用規約上も問題ありません
- Gemini側の標準マイク機能は使いません。両サイトともこの拡張機能自身のWeb Speech API(STT/TTS)で統一的に操作します(Gemini標準マイクは「聞き続けるか1回で切れるか」の挙動を外部から制御できないため)
- 音声認識(入力側)は、Chromeの仕様上、音声データがGoogleのサーバーへ送信されます(無料ですが完全にローカル完結ではありません)。読み上げ(出力側)は端末内で完結します
- claude.ai / Gemini側のHTML構造は非公開・可変のため、入力欄・送信ボタン・応答テキストの自動検出がうまくいかない場合があります。その場合はサイドパネル下部の「手動セレクタ設定」で調整してください(手順は下記)

## インストール方法(未パッケージ状態での読み込み)

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」を有効にする
3. 「パッケージ化されていない拡張機能を読み込む」をクリックし、このリポジトリのフォルダを選択する
4. ツールバーの拡張機能アイコンから本拡張機能をクリックすると、サイドパネルが開く

## 使い方

1. claude.aiまたはGeminiのタブを開き、アクティブにする
2. サイドパネル中央のオーブをクリック(起動。まず「キーワード待ち受け」状態になる)
3. 「Claude」または「Gemini」と話しかける(どちらのAIを対象にするかの切り替え)
4. 切り替わると自動で本格的な聞き取りモードに入るので、続けて用件を話しかける
   (**キーワードと用件は分けて発話してください**。「Claude、今日の天気は?」のように1回の発話にまとめて話すと、
   キーワード検出後に用件の部分は拾われません。「Claude」→一呼吸置いて→「今日の天気は?」の順で)
5. 自動で文字起こし→対象AIの入力欄へ送信される
6. 応答が返ってきたら自動で読み上げられ、読み上げが終わると再び「キーワード待ち受け」に戻る
   (次の発話でも「Claude」または「Gemini」と呼びかける必要があります。同じAIを続けて使う場合も同様です)
7. 停止する場合はオーブを再度クリック

サイドパネル上部の「CLAUDE」「GEMINI」ボタンで、キーワードを使わず手動で対象AIを切り替えることもできます。

## 近未来HUD演出(見た目のみ)

サイドパネル中央のオーブ(旧マイクボタン🎤は廃止し、オーブ自体がクリック領域です)に、状態(停止中/キーワード待ち受け中/聞いている/読み上げ中/エラー)に応じて色・動きが変わるトラッキングHUD風アニメーションを表示します。シアン=キーワード待ち受け中(KEYWORD)、緑=聞いている(LISTENING)、青=読み上げ中(SPEAKING)、赤=エラー。オーブ周囲のダイヤルリングは対象AI(CLAUDE=オレンジ/GEMINI=青)の色で着色されます。

左上・左下のテレメトリー風テキスト(SYSTEM/MODEL/VOICE/SESSION/TOKENS/EST. COST/FPSおよびLAT/LON/ALT/HDG)は、雰囲気を出すための**装飾目的の表示**です。FPSのみ実際の描画フレームレート、TOKENSは送受信テキストの文字数からの粗い概算、EST. COSTは常に$0.00(追加コストが発生しない設計のため)。LAT/LON/ALT/HDGは実際の位置情報を一切使わない(Geolocation権限も無い)架空の値で、時間とともに緩やかに変化するだけの演出です。

いずれもあくまで見た目の演出で、会話の相手・仕組み(claude.ai / GeminiのブラウザページのAIチャットを音声で操作する)自体は変わりません。

## 読み上げ設定(速度・音声)

サイドパネルに「読み上げ速度」スライダー(0.5〜2.0倍、デフォルト1.0倍)と「読み上げ音声」ドロップダウンを追加しました。音声ドロップダウンは、その環境(OS・ブラウザ)で`speechSynthesis.getVoices()`から取得できる音声の一覧です。名前に「Enhanced」「Natural」「Premium」「Neural」等を含む高品質な音声がある場合、★高品質マークが付き、初回起動時はそれが自動で初期選択されます(無ければ「システム標準」のまま)。どちらの設定も`chrome.storage.local`に保存され、次回起動時も保持されます。**新たに有料の音声合成APIを追加することはしていません**(ブラウザに標準搭載されている音声の中から選べるだけです)。

## 定例文ボタン

よく使う指示文(役割・基本ルールの確認、「CLAUDE.mdを読んで」等)をボタンにして、押すとclaude.aiの入力欄に反映できます(**送信はされません**、自分で送信ボタンを押してください)。「定例文を編集」を開き、1行1フレーズで書いて保存すると反映されます。設定は`chrome.storage.local`に保存され、ブラウザ・端末をまたいでは同期されません。ボタンの表示文字は、そのまま送信される文言そのもの(長ければ省略表示、全文はホバーで確認可)です。

**2026-09-18追加**: 定例文の正本を`data/templates.json`(このリポジトリ)にも置いた。「📥 JSONから一覧を読み込む」ボタン(一覧モード)を押すと、タスク一覧と一緒に定例文もこのファイルの最新内容で上書きされる(`chrome.storage.local`の`cvb_templates`を更新)。新しいスキルの呼び出しフレーズ等を定例文に追加したい場合は、`data/templates.json`を更新してcommit・pushすれば、拡張機能自体の更新なしに各ブラウザへ反映できる。

## うまく動かないとき(手動セレクタ設定)

自動検出は「画面下部の入力欄らしき要素」「aria-labelにSend/送信を含むボタン」等のheuristic(推測)で動いています。claude.ai / Gemini側の実装変更等で検出に失敗する場合、以下の手順で手動指定できます。手動セレクタはページのlocalStorageに保存されるため、claude.aiとGeminiそれぞれで別々に設定できます(サイドパネルの「手動セレクタ設定」欄は、そのとき対象になっているタブ=現在のモードに対して読み書きします)。

1. 対象ページ(claude.aiまたはGemini)でF12(開発者ツール)を開き、Elementsタブで入力欄・送信ボタン・応答メッセージのHTML要素を確認する
2. その要素を一意に絞り込めるCSSセレクタを調べる(要素を右クリック→「Copy」→「Copy selector」等)
3. サイドパネル下部の「手動セレクタ設定」に、それぞれ入力する(入力すると自動的に反映される)

**特に`claude.ai/code`(Claude CodeのWeb版)は通常のclaude.aiチャットより画面構成が複雑なため、自動検出が誤った要素を掴みやすいです。** DevToolsのConsoleタブを開いた状態で話しかけると、`[cvb:claude] findComposerInput: ...`(Geminiでは`[cvb:gemini] ...`)のようなログが出るので、実際にどの要素が選ばれたか・送信ボタンが見つかったかを確認できます。ここで意図しない要素が選ばれている場合は、上記の手動セレクタ設定で入力欄・送信ボタンを明示的に指定してください。

**2026-09-18、メッセージ検出の不具合を確定的に修正**: これまで応答メッセージの検出は`div, article`+文字数という推測ベースのheuristicだったため、ページ上部の操作バー(モデル名・高速モード切替等)やサイドバーのセッション一覧らしき文言を、実際の返答と誤認して抽出してしまう不具合が3回(別々の原因で)発生していた。ユーザーがDevToolsで実機確認した結果、claude.ai/codeのメッセージ本文には`data-alluvium="true"`という専用のdata属性が付いていることが判明したため、`findMessageBlocks()`はこの属性を最優先で使うようになった(見つかった場合は推測ベースのheuristicを使わない)。Geminiなどこの属性を持たないサイトでは、引き続き従来のheuristicにフォールバックする。

## マイク使用時に「音声認識エラー: not-allowed」が出る場合

Chromeの仕様上、サイドパネルの画面からはマイクの許可ダイアログが正しく表示されないことがあります。この場合、状態表示の下に「マイクの許可ページを開く」ボタンが出るので、それを押して開いたタブ側で許可してください。一度許可すれば、以後サイドパネル側でも音声認識が使えるようになります。それでも解決しない場合は`chrome://settings/content/microphone`からこの拡張機能を直接「許可」に変更してください。

## 既知の制約

- claude.ai / Geminiの画面構成が変わると、自動検出・手動セレクタの両方が効かなくなる可能性があります(特にGeminiは今回追加したばかりで、claude.aiほど実機検証を重ねていません)
- 音声認識中に読み上げ音声をマイクが拾わないよう、読み上げ中はマイクを開かない設計にしていますが、スピーカーの音量やマイクの感度によっては誤検出する場合があります。イヤホン・ヘッドセットの使用を推奨します
- 応答の完了判定は「新しい応答ブロックが現れてから、700ms間画面に変化が無ければ完了とみなす」という簡易的な仕組みです。長い応答の途中で誤って完了と判定される場合があります
- キーワード待ち受け(「Claude」「Gemini」の検出)と、その後の用件の聞き取りは**別々の音声認識セッション**です。1回の発話でキーワードと用件をまとめて話すと、キーワード検出後の用件部分は拾われません。キーワードを言ってから一呼吸置いて用件を話してください
- 読み上げ音声の「Enhanced」「Natural」等の高品質音声は、OS・ブラウザ側に元々インストールされているものに限られます(この拡張機能側で音声データを追加することはありません)。環境によっては高品質な音声が1つも無く、選択肢が標準音声のみになる場合があります
- HUDのテレメトリー表示(TOKENS/EST. COST/LAT/LON/ALT/HDG等)は演出目的のダミー・概算表示です。正確な使用量や実際の位置情報を示すものではありません
